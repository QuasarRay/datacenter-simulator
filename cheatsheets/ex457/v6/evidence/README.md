# Evidence and reproduction

Start with [v6 changes](v6-changes.md), [all 103 historical findings](audit-history.md), [the source mapping](content-to-sources.md), [the official-document audit](official-doc-audit.json), and [the CI/testing guide](../21_v6_tests_ci.md).

`audit-history.json` records the source hash, implementation/test mapping and acceptance boundary for each available finding. It includes the 32 v3 findings carried in v4's table; the original v3 audit was not available. `input-provenance.json` preserves the uploaded and previous-release hashes. No unseen audit generation is claimed.

The 23-objective [blueprint matrix](../00_blueprint_map.md), legacy source table, source review notes, v4 disposition table and historical table are generated by `tools/render_evidence.py`. The release validator requires those human files to match their registries exactly. Those mappings can include upstream/community sources and remain useful for provenance, but a URL or review note alone does not establish entailment or Red Hat product support.

For exam/product facts, use the stricter independent layer:

- `official-source-quotes.json` contains only retrieved Red Hat or Ansible documentation, with version/scope, locator and short direct quotations.
- `official-doc-audit.json` classifies every `claims.json` entry as official-document, mixed, repository/runtime, or outside the Red Hat/Ansible scope; it records the reviewed verdict and does not force pack policy into vendor prose.
- `runtime-doc-contracts.json` links selected documented mechanisms to named live pyATS observations.
- `tools/documentation_contract.py` freezes those mappings and rejects provenance/product-authority weakening. Hypothesis mutation tests exercise the fail-closed behavior.

The audit found one material current-product mismatch: the older Controller chapter treated the pinned `awx.awx` harness as the CaC path and described `infra.aap_configuration` as old. Red Hat's AAP 2.6 documentation says `infra.aap_configuration` incorporates the older component-specific configuration collections and should be used in their place. Chapter 12 now treats `awx.awx 24.6.1` only as this repository's upstream compatibility harness; real AAP 2.6 practice must use the supported collection available in the assigned environment.

Actual local validation is recorded in `local-validation.json` and the accompanying logs when present. Live results are `artifacts/results.json` in the GitHub Actions artifact for the specific commit/run. A missing report is not a pass. The default pipeline explicitly reports external Controller, entitled EE, CachyOS and RHEL reboot gates as NOT_RUN.

The unsigned manifest covers the exact release file set and detects omitted, added, duplicated or changed files. It excludes itself, `.state`, dependencies, caches and generated build context. It proves integrity against its index, not publisher authenticity. Runtime secrets and backups are excluded from distributable ZIPs.
