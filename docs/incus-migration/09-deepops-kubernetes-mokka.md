# DeepOps, Kubernetes and Mokka on Incus nodes

## DeepOps is an OS port, not a new image label

The checked integration runs pinned NVIDIA DeepOps Slurm playbooks on Ubuntu QEMU guests. Its `setup.sh`, `config.example.json`, `deepops.rs`, `deepops_runtime.rs`, `vm.rs`, inventory preparation, GPU policy and CI all contain assumptions that require review. A CachyOS Incus node does not satisfy those assumptions automatically.

Create a task-level portability inventory of the consumed DeepOps roles: package manager/repositories, service/unit names, Python/Ansible versions, filesystem paths, kernel/sysctl changes, NVIDIA driver/toolkit handling, munge, Slurm, PMIx/OpenMPI, NHC, users/groups, cgroups and reboot behavior. Record every fact gate and distribution-specific include. Port roles in a maintained fork or a narrowly documented adapter; do not set `ansible_distribution=Ubuntu` or remove assertions to get past unsupported tasks.

Move kernel/driver/storage operations to the qualified CachyOS host role. Keep Slurm controller/compute userspace and service configuration inside Incus. Build/install unavailable packages through a reviewed, pinned CachyOS package workflow, not arbitrary AUR scripts executed as root. Pin and test build dependencies, signatures and artifacts. Verify the actual service units and cgroup configuration generated by those packages.

Future conversion sequence:

1. Replace VM image/hash/VFIO config with Incus fingerprint/project/profile and GPU allocation policy. Keep all-zero example digests non-executable. Preserve compute-count validation and resource planning.
2. Replace QEMU/TAP/cloud-init provisioning with the common Incus transaction. Generate SSH trust/inventory from verified ready nodes, then require the resolved inventory to contain only intended targets before DeepOps executes.
3. Apply the CachyOS role port to a CPU-only controller/compute topology first. Check munge consistency, time assumptions, Slurm registration and a genuine CPU job. Report GPU stages `NOT_RUN` rather than faking GRES.
4. Qualify the real GPU profile from [08](08-gpu-nccl-rdma-infiniband.md). Run upstream validation and build the pinned NCCL/nccl-tests inputs for the guest ABI.
5. Preserve the current eleven MPI benchmark families, required roots/reductions/message ranges and correctness reporting. Retain explicitly unchecked upstream in-place cases as unchecked. Verify expected hostnames, ranks, GPUs and actual Socket/fabric settings.
6. Constrain MPI bootstrap/data/OOB as well as NCCL. A correct NCCL interface selection cannot prevent MPI from using management. Test data cut/failure/recovery with management still available.

At cutover remove `vm` feature/runtime commands, QEMU packages, qcow2/cloud-init artifacts and Ubuntu provisioning instructions from the supported path. Preserve old code only in Git history or clearly inert historical fixtures. Hardware-boot behavior remains a host exercise, not an Incus node feature.

## Replace Kind with Kubernetes machines in Incus

Retire `kind.ci.yaml`, Kind contexts, Docker node inspection/exec, Docker registry networking and Docker image building. Provision a small cluster of CachyOS system containers through Ansible: one real control plane and one or two workers initially. The current user mandate selects pinned Rusternetes control-plane components and KWOK synthetic workers. Qualify their discovery, watch, admission and controller semantics before claiming Mokka or NVIDIA operator compatibility. Use upstream Kubernetes only for a documented unavoidable NVIDIA dependency exception.

A real upstream kubelet requires a CRI runtime. The current Rusternetes + KWOK route does not run a kubelet or execute pods; real workloads run as native services in Incus. Incus is not a CRI runtime and cannot replace a pod with an Incus instance without a new incompatible runtime integration. This does not retain Docker/Kind as infrastructure backends.

Qualify:

- cgroup v2 delegation and matched kubelet/containerd systemd cgroup settings; no writable host-wide cgroup mount;
- required kernel modules loaded on the host, namespaced sysctls, CNI capabilities, overlay/storage behavior and explicit nesting policy;
- node internal IP on the intended fabric, non-overlapping pod/service/management CIDRs, API advertise/listen addresses and DNS;
- containerd registry trust/auth, pinned pause/workload images and reproducible offline pulls;
- systemd dependency order, certificates, time, swap policy, resource limits and bounded journaling;
- hostPath/device access used by Mokka inside each node, without exposing host GPU devices to CPU mock nodes.

If the pinned Kubernetes/CNI stack cannot run under the selected unprivileged profile, report that capability blocked and design the narrow required permission change. Do not automatically switch every node to privileged or mount the host root. Test the chosen profile on a disposable CachyOS host before scaling.

patchbay controls the node underlay. CNI may use encapsulation and virtual switches inside nodes. Verify pod-to-pod, pod-to-service and API traffic separately, with counters on the actual underlay and deliberate partitions. A node graph does not prove pod traffic follows a particular cable; a `hostNetwork` pod has another boundary. Test MTU/encapsulation, DNS failure and asymmetric paths.

## Mokka build and runtime

Keep the exact NVIDIA/k8s-test-infra source integrity, upstream tests and Helm chart behavior. Build its OCI artifact through a qualified Docker-free OCI build process on the dedicated build node, then publish via a native registry service or verified OCI transfer into containerd. Incus system-image publication is a different operation. Record source revision, build inputs and the **running** OCI digest, not merely a local tag.

Port config context/node names to the new cluster. Preserve existing namespace ownership, CPU-node opt-in, no-existing-GPU-capacity checks, GPU profile/count validation, chart contamination checks, tool executable identity and atomic Helm rollback. Disable the same independent IB mocks and driver injection features excluded by the current code. Inspect one expected deployment per chosen node and run actual upstream NVML consumers.

Test partial Helm batch failure and complete cleanup, node restart, CNI failure, wrong image digest, changed chart, unavailable registry, stale node name and accidental physical GPU node selection. Mokka success proves mock software contracts; it never enables native CUDA on a CPU-only machine.

## Scale and operational boundaries

Measure etcd/control-plane resident memory, API watch load, image storage, pod density, CNI/conntrack state, process count and pressure. Incus saves guest-kernel overhead but does not make hundreds of real control planes cheap. KWOK may later model workers, but it is not currently part of this migration and cannot be counted as a real master node or Mokka runtime.
